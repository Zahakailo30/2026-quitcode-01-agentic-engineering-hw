## Промпт B — структурований

```
Роль: ти senior React-розробник, який працює з дизайн-системою
Porsche Design System (PDS).

Контекст: Next.js 16 (App Router, TypeScript) застосунок «Камінь-Ножиці-Папір».
Ігровий компонент — app/components/RockPaperScissorsGame.tsx ('use client'),
його стан: round (поточний раунд: player/computer/result) і score (лічильники
win/lose/draw). UI зібраний виключно з PDS-компонентів, імпорт з
@porsche-design-system/components-react/ssr: PButton, PText, PTag.
Layout-стилі — у сусідньому *.module.css.

Завдання: додати під рахунком історію останніх раундів.

Обмеження:
- UI будувати лише з компонентів PDS; ручний CSS припустимий тільки для
  layout (flex/grid/відступи) у *.module.css
- зберігати не більше 5 останніх раундів
- кнопка «Reset score» має очищати також історію
- не додавати нових npm-залежностей
- TypeScript strict, без any

Критерії приймання:
- npm run lint і npm run build (у теці app/) проходять без помилок
- історія оновлюється після кожного ходу, найновіший раунд — зверху
- коли історія порожня — блок історії не рендериться взагалі

Формат відповіді: спершу перелік файлів, які зміниш; потім суть змін;
наприкінці — фактичний результат запуску npm run lint і npm run build.
```

| Ручні візуальні стилі | так (фон і радіус рядків) | ні, тільки layout-CSS |

**Дефекти, які не ловлять ні lint, ні build (обидва в A):**

1. Вигаданий CSS-токен `--p-color-background-surface` — такого в PDS немає
   (є `--p-color-surface`). Фон рядків мовчки падає у fallback
   `rgba(0,0,0,0.03)` — на темній темі невидимий.
2. `useRef`-лічильник не скидається у `handleReset`: після «Reset score»
   рахунок 0, а перший же новий запис в історії підписаний **#4**.

У B знайшовся лише один дрібний смішок — `key={index}` для списку.

## Висновок

Структурований промпт коштував **на 11% більше токенів за ту саму кількість
ітерацій** — і це вся його ціна. Натомість базовий промпт дав код, який
проходить **усі автоматичні перевірки**, але має два дефекти, помітні лише
очима, ігнорує конвенції проєкту (UI тільки з DS-компонентів) і ставить блок
не туди, зруйнувавши центрування, яке робили окремою ітерацією раніше.

Головне: **економія на промпті не зникає, а переїжджає в рев'ю**. Виправлення
двох дефектів A — це щонайменше ще одна ітерація з поясненням контексту, тобто
дорожче за ті 5.5k токенів, які «зекономив» короткий промпт. Найбільше змінили
результат не «роль» і не «формат відповіді», а **обмеження** і **критерії
приймання**: саме вони прибрали вигадані числа (5 замість 10), тримали UI в
межах дизайн-системи й задали правильне місце блоку.
